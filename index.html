START
The task branch is complete and its pull request is ready for formal review.LIVE CONTROLLED PATH
NON-NEGOTIABLE RULE

Only a reviewed pull request can change protected main. A successful merge triggers staging; it never directly triggers production.

  1. 01
    HUMANEngineer / agent
    GitHub pull request

    Mark the PR ready and provide scope, test evidence and rollback notes.

    OUTPUT

    A reviewable change tied to one commit SHA.

  2. 02
    AUTOMATICGitHub
    Six ops-ci runners

    Run the complete required CI inspection line.

    OUTPUT

    Twelve gate results attached to the PR.

  3. 03
    DECISIONGate decision
    GitHub branch protection

    Are every required check and policy condition green?

    OUTPUT

    Review eligibility or a hard stop.

    YES / PASS →

    Continue to Step 4.

    NO / FAIL ↩

    Merge is blocked. Repair the branch, push again and repeat Step 2.

  4. 04
    HUMANHuman reviewer
    GitHub pull request

    Review the change, evidence, impact and separation from other tasks.

    OUTPUT

    Approval or specific requested changes.

  5. 05
    DECISIONReview decision
    Protected main

    Is the PR approved and still up to date?

    OUTPUT

    Permission to merge or a return-to-work loop.

    YES / PASS →

    Merge the PR and continue to Step 6.

    NO / FAIL ↩

    Return to the same task branch; then repeat checks and review.

  6. 06
    AUTOMATICGitHub
    Release workflow + registry

    Record the merged SHA and build the traceable staging release.

    OUTPUT

    A named release candidate linked to source and CI evidence.

  7. 07
    AUTOMATICCoolify
    Permanent Staging VPS 12

    Automatically deploy that release to the correct staging application.

    OUTPUT

    ElevateTech or Ops staging runs the merged version.

  8. 08
    AUTOMATICCI + monitoring
    Staging, Kuma, Grafana + ITAgent

    Run smoke journeys and watch application and host health.

    OUTPUT

    Deployment, health, alert and recovery evidence.

  9. 09
    DECISIONStaging decision
    Release evidence

    Is staging healthy and accepted by the reviewer?

    OUTPUT

    Production eligibility or a contained staging failure.

    YES / PASS →

    Finish this journey. The release may enter manual Production promotion.

    NO / FAIL ↩

    Stop promotion. Roll back staging if needed and repair through a new PR.

FINISHPermanent staging runs the approved main commit, smoke evidence is recorded, and production is still unchanged.
