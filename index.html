1Ready for reviewYou (or the agent) flip the draft when the work is done. Blocked automatically while the draft checks are red.

4PromoteActions → “Promote Production” → enter the SHA. ElevateTech: Wade. OPS App: Nicholas. Everyone else is refused by name.

What the CI gates actually check

CorrectnessTypecheck, lint, unit tests — scoped to what your diff touches on drafts, everything on ready.
SecuritySecret scan (gitleaks), dependency audit, container scan (trivy), authorization / BOLA tests.
Product safetyAuth invariants & org/branch scoping, database migration diff review, visual regression (OPS, dedicated runner).
DeployabilityCompose & environment contracts prove the release can actually deploy before it may merge.
Build onceOn merge, images are built a single time and digest-pinned. Staging and production run those exact bytes.
CertificationStaging must pass deploy proofs + smoke + full E2E journeys before a SHA becomes promotable.
Pre-push on your machine is ~1 second: formatting on changed files, secret scan, contract checks. The heavy work runs in CI on every draft push — and cancels itself when you push again.

Hotfixes

There is deliberately no shortcut to staging or production. A hotfix is the same loop at speed: branch → PR (skip the preview label) → Ready → gates → merge → staging re-certifies (~30–40 min). For a production incident, promote the last certified SHA — the promote button physically refuses anything uncertified, including rollbacks to known-good releases, which are always available.
